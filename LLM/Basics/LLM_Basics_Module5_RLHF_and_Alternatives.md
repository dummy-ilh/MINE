# Module 5 — Alignment: RLHF & Alternatives (Master Notes, Maximum Depth)

## 0. Why alignment is a separate stage at all

An instruction-tuned model (end of Module 4) already follows instructions, but instruction tuning trains on a single "correct" demonstration per example — it has no way to express **degrees of preference** ("Answer A is better than Answer B, but both are acceptable") or to be steered toward diffuse human values (helpfulness, harmlessness, honesty) that are hard to write a single ground-truth demonstration for. Alignment methods (RLHF, DPO, and their relatives) exist to incorporate **comparative human judgment** — "which of these two responses do you prefer?" — as the training signal, which is a fundamentally different (and richer, but noisier) supervision signal than "here is the one correct answer."

**The full pipeline, end to end**:
```
Pretrained base model
   → SFT (Supervised Fine-Tuning, = instruction tuning from Module 4)
      → Reward Model training (on human preference comparisons)
         → RL fine-tuning (PPO) using the reward model as the reward signal
```
DPO (covered in section 4) collapses the last two stages into one, skipping the explicit reward model and RL loop entirely — this is why it's called "direct."

---

## 1. Stage 1 recap — SFT (Supervised Fine-Tuning)

This is exactly instruction tuning from Module 4: human-written (prompt, ideal-response) pairs, standard cross-entropy loss (same formula as CLM from Module 2, just restricted to fine-tuning data). The output of this stage — call it `π_SFT` — is the **starting policy** for everything that follows. It's important to name this precisely because both PPO and DPO explicitly reference `π_SFT` as a fixed reference point later.

---

## 2. Stage 2 — Reward Model (RM) training

### The data collection process
Humans are shown a prompt and **multiple candidate responses** generated by `π_SFT` (typically 2 at a time, sometimes ranked lists of 4+), and asked to pick which response they prefer. This produces a dataset of `(prompt, response_chosen, response_rejected)` triples — critically, **humans are never asked to assign an absolute numeric score** ("rate this 7/10") because absolute scoring is noisy and inconsistent across raters/time; relative comparisons are much more reliable for humans to give consistently.

### The Bradley-Terry model — the actual math

The Bradley-Terry model is a classical statistics model (originally for ranking chess players / sports teams from pairwise match outcomes) repurposed here. It assumes each response `y` has some latent, unobserved "true quality" scalar `r(y)` (the reward), and the **probability that a human prefers response `y_w` (winner) over `y_l` (loser)** is:

```
P(y_w ≻ y_l | x) = σ(r(x, y_w) - r(x, y_l)) = exp(r(x,y_w)) / (exp(r(x,y_w)) + exp(r(x,y_l)))
```

where `σ` is the sigmoid function, and `x` is the prompt. **In plain words**: the *larger the gap* between the two responses' true reward scores, the more confidently/consistently humans should prefer the better one; if the two rewards are equal, the model predicts a 50/50 coin-flip preference, matching intuition.

### Training the reward model
We don't know the true `r(x,y)` — that's exactly what we're trying to learn. We parameterize `r` as a neural network (typically initialized from the SFT model itself, with the language-modeling head replaced by a single scalar output head), and train it to **maximize the likelihood of the observed human preference data** under the Bradley-Terry formula above. This becomes a loss function:

```
L_RM = - log σ(r(x, y_w) - r(x, y_l))
```
(negative log-likelihood of the Bradley-Terry probability, exactly analogous to the cross-entropy loss pattern from Module 2 — "make the model assign high probability to what was actually observed.")

### Numerical worked example
Suppose the reward model currently outputs `r(x, y_w) = 2.0` and `r(x, y_l) = 0.5` for a given comparison where humans indeed preferred `y_w`.

```
P(y_w ≻ y_l) = σ(2.0 - 0.5) = σ(1.5) = 1 / (1 + e^-1.5) ≈ 1 / (1 + 0.223) ≈ 0.817
```
Loss = `-log(0.817) ≈ 0.202` — a fairly small loss, since the model already assigns high probability (81.7%) to the correct preference direction.

Now suppose instead the model had it backwards: `r(x, y_w) = 0.5`, `r(x, y_l) = 2.0` (rejected response scored higher — a mistake):
```
P(y_w ≻ y_l) = σ(0.5 - 2.0) = σ(-1.5) = 1/(1+e^1.5) ≈ 1/(1+4.48) ≈ 0.182
Loss = -log(0.182) ≈ 1.70
```
Much larger loss (1.70 vs 0.202) — the reward model is penalized heavily for confidently ranking the human-rejected response higher, pushing gradients to widen the gap `r(y_w) - r(y_l)` in the correct direction.

### What the trained reward model gives you
A single scalar function `r(x, y)` that takes any (prompt, response) pair and outputs a number — higher means "a human would probably prefer this response." This scalar becomes the **reward signal** for the next stage, replacing the need for a human in the loop for every single training example going forward (the human effort was spent once, up front, to train this proxy).

## 3. Stage 3 — RL fine-tuning with PPO

### Why RL at all, and why not just directly maximize `r(x,y)` with gradient ascent
You can't directly backpropagate through sampling a discrete text sequence in a simple way (sampling tokens is non-differentiable) — this is exactly the classic RL setting: an **agent** (the language model, viewed as a "policy" `π_θ` that outputs a probability distribution over next actions=tokens) takes actions in an **environment** (generating text token by token) to maximize a **reward** (the reward model's score on the finished response). PPO (Proximal Policy Optimization) is the specific RL algorithm used because it's stable and sample-efficient for this kind of high-dimensional, sequential action space.

### The naive objective (and why it needs fixing)
The simplest thing you could write is: "maximize expected reward":
```
maximize E[ r(x, y) ]  where y ~ π_θ(y|x)
```
**The problem — reward hacking**: if you optimize purely for the reward model's score with no constraint, the policy will drift far from `π_SFT` and find inputs/outputs that exploit quirks or blind spots in the reward model (which is, after all, an imperfect learned approximation of true human preference, not the ground truth itself) — producing text that scores artificially high on the reward model while actually being incoherent, repetitive, or otherwise degenerate to an actual human reader. This is a critical, very commonly-tested interview concept: **the reward model is a proxy, and unconstrained optimization against a proxy metric famously breaks it (Goodhart's Law: "when a measure becomes a target, it ceases to be a good measure").**

### The fix — KL penalty against the reference policy
PPO's actual objective for RLHF adds a penalty term that keeps the new policy `π_θ` close to the original SFT policy `π_SFT` (called the **reference model**, kept frozen throughout this stage):

```
Objective = E[ r(x, y) ] - β × KL(π_θ(y|x) || π_SFT(y|x))
```

- `KL(π_θ || π_SFT)` = the **KL divergence** between the current policy's output distribution and the frozen reference policy's output distribution — a standard information-theoretic measure of "how different are these two probability distributions." It's always ≥ 0, and exactly 0 only when the two distributions are identical.
- `β` (beta) = a tunable coefficient controlling how strongly you penalize drifting from the reference — small β allows more reward-chasing (and more risk of reward hacking); large β keeps the model very close to `π_SFT` (safer, but limits how much the reward signal can actually improve behavior).

**In plain words**: "get a higher reward-model score, but don't drift too far from how the original instruction-tuned model behaved" — this directly bounds the reward-hacking failure mode, because a policy that's forced to stay statistically close to `π_SFT` can't wander into the weird, degenerate corners of output-space where the reward model's approximation breaks down.

### PPO's actual clipped objective (the specific mechanism, not just "KL-penalized RL" in general)
The full PPO objective (as typically applied here) also includes a **clipping mechanism** on the policy-ratio term, on top of the KL penalty, for additional training stability:
```
r_t(θ) = π_θ(a_t|s_t) / π_θ_old(a_t|s_t)   (ratio of new policy to old policy probability for the action taken)

L_PPO_clip = E[ min( r_t(θ) × A_t,  clip(r_t(θ), 1-ε, 1+ε) × A_t ) ]
```
- `A_t` = the **advantage** at step t (roughly: "how much better was this action than average," estimated using the reward signal and a learned value function — the exact estimator commonly used is GAE, Generalized Advantage Estimation, worth knowing the name of but not required to derive in most MLE interviews).
- `clip(r_t(θ), 1-ε, 1+ε)` = clamps the policy-ratio to a small window around 1 (e.g. ε=0.2 means the ratio is clamped to [0.8, 1.2]).
- Taking the `min` of the unclipped and clipped versions means: **if the update would move the policy ratio too far in a direction that increases the objective, PPO caps the benefit it gets from that — this discourages taking overly large policy update steps in a single iteration**, which is exactly what "Proximal" in the name refers to (stay proximal/close to the previous policy, step by step, rather than taking one huge potentially-destabilizing leap).

**Interview-level summary sentence**: "PPO for RLHF has two separate stability mechanisms working together: a KL penalty against the frozen SFT reference model (prevents drifting into reward-hacking territory over the whole training run), and a clipped surrogate objective (prevents any single gradient update step from being too large) — the first is about *where you end up*, the second is about *how big a step you take at a time*."

### Numerical intuition for the KL term
Suppose for a given prompt, `π_SFT` puts 90% probability on token "helpful", and the current `π_θ` (mid-training) puts 40% probability on "helpful" (having shifted toward some other completion the reward model seems to like). Roughly, larger probability mismatches like this contribute more to the KL divergence sum, which increases the penalty term, pulling gradients back toward restoring higher probability on tokens the reference model favored — the exact per-token KL contribution follows `p_θ(y) × log(p_θ(y)/p_SFT(y))`, summed/integrated over the output distribution; the key qualitative point is that **large probability shifts away from the reference are penalized more than small ones**, giving a smooth, differentiable brake on drift.

## 4. DPO (Direct Preference Optimization) — full derivation

### The motivating insight
DPO's core contribution is a mathematical trick: it's possible to show that the **optimal policy** for the exact KL-constrained reward-maximization objective from Section 3 above has a **closed-form relationship to the reward function** — meaning you don't need to actually run RL (PPO, rollouts, value functions, advantage estimation, all of that machinery) at all. Instead, you can **substitute this closed-form relationship directly into the Bradley-Terry preference loss from Section 2**, producing a loss you can optimize with plain supervised learning (just gradient descent on a closed-form loss, no sampling/rollouts needed).

### The derivation, step by step

**Step 1**: The KL-constrained RL objective from Section 3 (maximize reward, penalize KL divergence from reference) has a known closed-form optimal solution (this result predates DPO — it's from earlier RL-as-inference / control-as-inference literature):
```
π*(y|x) = (1/Z(x)) × π_SFT(y|x) × exp( (1/β) × r(x,y) )
```
- `Z(x)` is a normalization constant (a "partition function," summing over all possible responses y so the distribution sums to 1) — this term is famously **intractable to compute directly** (you'd need to sum/integrate over every possible text output, which is combinatorially impossible) — this intractability is exactly why, historically, people used RL/PPO instead of directly working with this formula.

**Step 2**: Rearrange the equation above to solve for `r(x,y)` in terms of the policy (algebraically invert it):
```
r(x,y) = β × log( π*(y|x) / π_SFT(y|x) ) + β × log Z(x)
```
**The DPO insight**: notice that `Z(x)` depends only on the prompt `x`, not on the specific response `y`. Recall the Bradley-Terry preference probability formula from Section 2 only ever involves a **difference** of two reward values, `r(x,y_w) - r(x,y_l)`, for the *same* prompt `x` — and since `β log Z(x)` is identical for both `y_w` and `y_l` (same prompt), **it cancels out exactly** when you take that difference:
```
r(x,y_w) - r(x,y_l) = β log(π*(y_w|x)/π_SFT(y_w|x)) - β log(π*(y_l|x)/π_SFT(y_l|x))
```
The intractable `Z(x)` term is gone — this cancellation is the entire mathematical trick that makes DPO work.

**Step 3**: Substitute this reward-difference expression directly into the Bradley-Terry loss from Section 2 (`L = -log σ(r(y_w)-r(y_l))`), and relabel `π*` as `π_θ` (the policy we're now directly training) to get the **DPO loss**:
```
L_DPO(θ) = -log σ( β log(π_θ(y_w|x)/π_SFT(y_w|x)) - β log(π_θ(y_l|x)/π_SFT(y_l|x)) )
```

**What this formula means in plain words**: train the policy directly (via ordinary gradient descent, using the same preference data you'd have collected for reward-model training) to **increase the log-probability ratio of the preferred response relative to the reference model, and decrease that ratio for the rejected response**, with `β` controlling how aggressively to do this (same role as the KL-penalty coefficient in PPO, now baked directly into this single loss formula rather than being a separate RL hyperparameter). **No reward model is ever explicitly trained; no RL rollouts, value functions, or advantage estimates are ever computed.**

### Numerical worked example
Say for a given (prompt, chosen, rejected) triple, and β=0.1:
- `π_θ(y_w|x) = 0.30`, `π_SFT(y_w|x) = 0.20` → ratio = 1.5, log(1.5) ≈ 0.405
- `π_θ(y_l|x) = 0.10`, `π_SFT(y_l|x) = 0.15` → ratio = 0.667, log(0.667) ≈ -0.405

```
Inner term = β × [0.405 - (-0.405)] = 0.1 × 0.81 = 0.081
L_DPO = -log σ(0.081) = -log(0.520) ≈ 0.653
```
This shows the model is already moving in the right direction (higher probability than reference for the chosen response, lower for the rejected one), giving a moderate loss that will keep pushing that gap wider via gradient descent — same qualitative behavior as watching the Bradley-Terry loss shrink in Section 2's worked example, just computed directly from policy log-probability ratios instead of from a separately-trained reward model's scalar outputs.

### Why DPO became popular — the practical tradeoffs (a very likely interview question)
**Advantages**: far simpler implementation (standard supervised-learning-style loss, no RL infrastructure — no rollout sampling, no separate value-function network, no advantage estimation, no clipping hyperparameters), more stable training (RL/PPO is notoriously sensitive to hyperparameters and prone to instability/collapse), and cheaper compute (skips training and running a whole separate reward model network during the main training loop).

**Disadvantages / open tradeoffs to mention for a balanced answer**: DPO's derivation assumes the Bradley-Terry model perfectly and implicitly ties the "reward" concept to the policy itself, which some argue makes it less flexible than having an explicit, reusable, inspectable reward model (e.g., you can't easily use a PPO-trained reward model to also do best-of-N reranking or automated red-teaming/evaluation the way you can with an explicit standalone reward model). There's also ongoing research debate over whether DPO and PPO reach genuinely equivalent final policies in practice, or whether PPO's online exploration (actually sampling and scoring new rollouts during training) gives it access to preference signal in regions of output-space that DPO's offline, fixed-dataset approach never explores.

## 5. Other alignment variants (know these exist + the one differentiator each — common "have you heard of X" interview check)

- **RLAIF (RL from AI Feedback)**: same pipeline as RLHF, but the pairwise preference labels (which response is better) are generated by **another LLM** instead of human annotators — dramatically cheaper/faster to scale than human labeling, with the obvious tradeoff that you're now aligning to an AI's judgment of preference rather than a human's (which could inherit or amplify that AI's own biases/blind spots).

- **Constitutional AI (Anthropic)**: a specific two-phase RLAIF-style approach where a model critiques and revises its own outputs according to a written set of principles (a "constitution"), generating the training data for both an SFT-style phase (self-critique-and-revise) and an RLAIF-style preference phase — the key idea is reducing direct reliance on human-labeled harmful-content examples by having the model reason about a constitution instead.

- **IPO (Identity Preference Optimization)**: a modification to DPO's loss function motivated by a theoretical concern that DPO (like the Bradley-Terry model itself) can overfit/become overconfident on preference pairs that are very "easy" (large probability gaps), since the sigmoid-log-loss keeps pushing the gap wider even after it's already large and correct — IPO uses a different (squared-error-style) loss shape that saturates instead of continuing to push indefinitely, intended to be more robust to noisy or over-represented preference data.

- **KTO (Kahneman-Tversky Optimization)**: motivated by behavioral-economics prospect theory (hence the name, after Kahneman & Tversky) — instead of requiring *paired* preference comparisons (y_w vs y_l for the same prompt, which are expensive/slow to collect), KTO can train from **unpaired binary "good" / "bad" labels** on individual responses (much cheaper/more naturally available data, e.g. simple thumbs-up/thumbs-down signals), while incorporating loss-aversion-style asymmetric weighting between the two label types.

**One line to have ready if asked to compare all of these**: "They're all trying to solve the same core problem — get preference-style human/AI judgment into the model — but they differ in (a) whether they need an explicit reward model and RL loop (RLHF/PPO does, DPO/IPO/KTO don't), (b) whether the preference labels come from humans or another AI (RLHF vs RLAIF/Constitutional AI), and (c) whether they need paired comparisons or can use unpaired good/bad labels (DPO/IPO need pairs, KTO doesn't)."

## 7. Quick-fire Q&A (self-test)

**Q: Write the Bradley-Terry preference probability formula and explain what happens as the reward gap grows.**
A: `P(y_w ≻ y_l) = σ(r(y_w) - r(y_l))`. As the gap grows, sigmoid output approaches 1 (near-certain preference for the better response); as the gap shrinks to 0, probability approaches 0.5 (coin flip).

**Q: Why can't you just directly maximize the reward model's score with unconstrained RL?**
A: The reward model is a learned proxy for true human preference, not ground truth — unconstrained optimization exploits blind spots/quirks in the proxy (reward hacking, a Goodhart's Law failure), producing outputs that score well on the reward model but are actually degenerate to real humans.

**Q: What are PPO's two distinct stability mechanisms, and what does each one control?**
A: A KL-divergence penalty against the frozen SFT reference policy (controls overall drift from the starting policy across training) and a clipped surrogate objective on the policy ratio (controls the size of any single gradient update step).

**Q: What is the key algebraic trick that lets DPO eliminate the reward model and the RL loop?**
A: The closed-form optimal policy for the KL-constrained RL objective expresses reward as `r(x,y) = β log(π*/π_SFT) + β log Z(x)`; since the intractable partition function `Z(x)` depends only on the prompt (not the response), it cancels out exactly when computing the reward *difference* between a chosen and rejected response for the same prompt — which is all the Bradley-Terry loss ever needs.

**Q: In the DPO loss, what does the β coefficient control, and what's its RLHF/PPO equivalent?**
A: β controls how aggressively the policy is pushed to separate chosen vs rejected response probabilities relative to the reference model — it plays the same role as the KL-penalty coefficient β in PPO's objective, just baked directly into a single supervised loss instead of a separate RL constraint term.

**Q: What data format does KTO need that DPO/PPO do not, and why does that matter practically?**
A: KTO can train on unpaired binary good/bad labels on individual responses, rather than requiring paired (chosen, rejected) comparisons for the same prompt — this is practically valuable because unpaired thumbs-up/down-style feedback is far cheaper and more naturally available than curated pairwise comparisons.

**Q: If asked to pick RLHF vs DPO for a real production system, what's a balanced answer?**
A: DPO is simpler, cheaper, and more stable to implement since it skips the reward model and RL infrastructure entirely — a strong default choice. RLHF/PPO remains attractive when you want a standalone, reusable reward model (useful for reranking, evaluation, or red-teaming beyond just training the policy) or when online exploration during RL training might reach preference signal that a fixed offline preference dataset never covers.
