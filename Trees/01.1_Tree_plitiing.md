## Cheat sheet

 Method | Used for | Formula | Pure node value | Max value (binary) |
|---|---|---|---|---|
| Gini impurity | Classification | $1-\sum_i p_i^2$ | 0 | 0.5 |
| Entropy / information gain | Classification | $-\sum_i p_i\log_2 p_i$ | 0 | 1.0 |
| Misclassification error | Classification (rarely used for growing) | $1-\max_i p_i$ | 0 | 0.5 |
| Variance reduction (MSE) | Regression | $\frac{1}{n}\sum(y_j-\bar y)^2$ | 0 | unbounded |
| Chi-square (CHAID-style) | Classification, mainly categorical splits | $\sum \frac{(O-E)^2}{E}$ | — | — |
 | Gain Ratio (C4.5) | Classification, high-cardinality features | $\dfrac{\text{Info Gain}}{\text{Split Info}}$ |
| Twoing criterion | Classification, multiclass | see §6 |
| Chi-square (CHAID-style) | Classification, categorical splits | $\displaystyle\sum \frac{(O-E)^2}{E}$ |

## 1. Gini impurity

$$\text{Gini}(t) = 1 - \sum_i p_i^2$$

Plain meaning: the probability you'd misclassify a random point from this node, if you labeled points randomly according to the node's own class proportions.

**Parent Gini (Dataset A):**
$$\text{Gini} = 1 - 0.3^2 - 0.7^2 = 0.42$$

### Worked Field Example — X1 (Income) vs. X2 (Age)

**Split on X1 = `Income == low`** (rows 1-3 left, rows 4-10 right):

Left: 3 rows, 1 purchased → $p_1=1/3$. $\text{Gini}_L = 1-(1/3)^2-(2/3)^2 = 0.444$
Right: 7 rows, 6 purchased → $p_1=6/7$. $\text{Gini}_R = 1-(6/7)^2-(1/7)^2 = 0.245$

$$\text{Weighted Gini} = \tfrac{3}{10}(0.444) + \tfrac{7}{10}(0.245) = 0.305 \qquad \text{Gain} = 0.42-0.305 = \mathbf{0.115}$$

**Split on X2 = `Age <= 47.5`** (best threshold found by scanning all 9 candidate cut points on sorted age): left = rows with age in {22,25,30,35,40,45} (6 rows, 3 purchased), right = rows with age in {50,55,60,65} (4 rows, all 4 purchased — a pure right child).

Left: $p_1=0.5 \Rightarrow \text{Gini}_L = 1-0.25-0.25 = 0.5$
Right: pure $\Rightarrow \text{Gini}_R = 0$

$$\text{Weighted Gini} = \tfrac{6}{10}(0.5)+\tfrac{4}{10}(0) = 0.30 \qquad \text{Gain} = 0.42-0.30 = \mathbf{0.12}$$

**Result: X2 (Age) wins narrowly** (0.12 vs 0.115) — sklearn's `DecisionTreeClassifier(criterion='gini', max_depth=1)` on this exact table independently picks the `Age <= 47.5` split, matching the hand calculation.

## 2. Entropy / information gain

$$\text{Entropy}(t) = -\sum_i p_i \log_2 p_i$$

Plain meaning: average number of bits needed to state a random point's class, given the node's class distribution — a borrowed information-theory idea. Pure nodes need 0 bits; a 50/50 node needs the full 1 bit.

**Parent entropy (Dataset A):**
$$\text{Entropy} = -0.3\log_2 0.3 - 0.7\log_2 0.7 = 0.881$$

### Worked Field Example — same two splits as §1

**X1 (`Income == low`):** $\text{Entropy}_L = -\tfrac13\log_2\tfrac13-\tfrac23\log_2\tfrac23 = 0.918$, $\text{Entropy}_R = -\tfrac67\log_2\tfrac67-\tfrac17\log_2\tfrac17 = 0.592$

$$\text{Weighted} = 0.3(0.918)+0.7(0.592)=0.690 \qquad \text{Gain} = 0.881-0.690=\mathbf{0.192}$$

**X2 (`Age <= 47.5`):** $\text{Entropy}_L = -0.5\log_2 0.5-0.5\log_2 0.5 = 1.0$, $\text{Entropy}_R = 0$ (pure)

$$\text{Weighted} = 0.6(1.0)+0.4(0)=0.60 \qquad \text{Gain} = 0.881-0.60=\mathbf{0.281}$$

**Result: X2 (Age) wins again**, and by a wider margin under entropy (0.281 vs 0.192) than under Gini — consistent with the general pattern that entropy is somewhat more aggressive than Gini at rewarding a split that produces one perfectly pure child.

## 3. Gain Ratio (C4.5) — Fixing Information Gain's Cardinality Bias

$$\text{Split Info}(S) = -\sum_{v} \frac{|S_v|}{|S|}\log_2\frac{|S_v|}{|S|} \qquad \text{Gain Ratio} = \frac{\text{Info Gain}}{\text{Split Info}}$$

Plain meaning: Split Info measures how much a split "spreads" the data across branches, regardless of purity. Dividing by it penalizes splits that achieve their gain mainly by fragmenting the data into many small, trivially-pure groups.

### Worked Field Example — X1 vs. X2, then the cardinality-bias case

**X1 (`Income`, 3/7 split via `==low` vs. rest):**
$$\text{Split Info} = -\tfrac{3}{10}\log_2\tfrac{3}{10}-\tfrac{7}{10}\log_2\tfrac{7}{10} = 0.881 \qquad \text{Gain Ratio} = \frac{0.192}{0.881} = \mathbf{0.218}$$

**X2 (`Age <= 47.5`, 6/4 split):**
$$\text{Split Info} = -\tfrac{6}{10}\log_2\tfrac{6}{10}-\tfrac{4}{10}\log_2\tfrac{4}{10} = 0.971 \qquad \text{Gain Ratio} = \frac{0.281}{0.971} = \mathbf{0.289}$$

Age still wins (0.289 > 0.218), consistent with §1-2.

**Now the cardinality-bias illustration:** add a hypothetical third column, `customer_id` (1 through 10, unique per row) to Dataset A. Splitting on it puts each of the 10 customers in their own leaf — every leaf pure, so raw Information Gain equals the full parent entropy, $0.881$ — the maximum possible, despite the feature being useless for new customers.

$$\text{Split Info} = -\sum_{i=1}^{10}\tfrac{1}{10}\log_2\tfrac{1}{10} = \log_2 10 \approx 3.322 \qquad \text{Gain Ratio} = \frac{0.881}{3.322} \approx \mathbf{0.265}$$

Even after the penalty, `customer_id` (0.265) still edges out both real features here — a useful caution that Gain Ratio reduces cardinality bias substantially but doesn't eliminate it, especially in small samples. C4.5's practical guardrail: only rank by Gain Ratio among features whose *raw* Information Gain is at least the average Information Gain across all candidates, which filters out features whose gain came purely from fragmentation.

## 4. Misclassification error

$$\text{Error}(t) = 1 - \max_i p_i$$

Plain meaning: if you predicted the majority class for every point in this node, what fraction would you get wrong? Almost never actually used to *grow* trees — §7 shows exactly why.

**Parent error (Dataset A):** majority class = purchased (7/10), so $\text{Error} = 1-0.7 = 0.3$.

### Worked Field Example — the same two splits, now under misclassification error

**X1 (`Income == low`):** Left (3 rows, 1 purchased): majority = "no", error $=1/3$. Right (7 rows, 6 purchased): majority = "yes", error $=1/7$.
$$\text{Weighted} = 0.3(1/3)+0.7(1/7) = 0.2 \qquad \text{Gain} = 0.3-0.2 = \mathbf{0.10}$$

**X2 (`Age <= 47.5`):** Left (6 rows, 3 purchased): a tie, $p=0.5$, error $=0.5$. Right (4 rows, all purchased): pure, error $=0$.
$$\text{Weighted} = 0.6(0.5)+0.4(0)=0.30 \qquad \text{Gain} = 0.3-0.30 = \mathbf{0.00}$$

**This is the punchline, live in real data:** misclassification error assigns `Income` a *positive* gain (0.10) and `Age` a gain of *exactly zero* — completely failing to notice that the `Age` split produces a perfectly pure child and is, by Gini and entropy (§1-2), clearly the better split (0.12/0.281 vs. 0.115/0.192). A tree grown with misclassification error as the criterion would pick `Income` here and miss the better split entirely.

## 5. Variance reduction (MSE) — for regression

$$\text{MSE}(t) = \frac{1}{n}\sum_{j\in t}(y_j-\bar y_t)^2$$

Plain meaning: impurity for a numeric target is just how spread out the values are around their own mean. Variance reduction is parent MSE minus weighted child MSE — the same "gain" pattern as Gini/entropy.

### Worked Field Example — X1 (Sqft) vs. X2 (House Age)

**Split on X1 = `Sqft <= 1375`:** Left = rows 1,2,3,4,5 (prices 150,180,190,230,240), mean $=198.0$. Right = rows 6,7,8,9,10 (prices 300,310,340,380,400), mean $=346.0$.

$$\text{SS}_L = 3000.0,\quad \text{SS}_R = 3000.0 \quad\Rightarrow\quad \text{Weighted MSE} = \frac{3000+3000}{10} = 600.0$$
$$\text{Variance Reduction} = 6776.0 - 1300.0 = \mathbf{5476.0}$$

(Matches sklearn's `DecisionTreeRegressor(max_depth=1)`, which picks this exact threshold, with leaf predictions 198.0 / 346.0 — exactly the group means.)

**Split on X2 = `House Age <= 4.5`** (best age threshold found by scanning all 9 candidates): Left = rows with age in {1,2,3,4} → prices {340,300,190,400}, mean $=307.5$. Right = rows with age in {5,8,10,15,20,25} → prices {150,240,380,230,180,310}, mean $=248.33$.

$$\text{Variance Reduction} = 6776.0 - 5935.83 = \mathbf{840.17}$$

**Result: X1 (Sqft) dominates** (5476.0 vs. 840.17) — matches physical intuition, since square footage drives price far more directly than the house's age in this data. This is also a useful reminder that not every feature comparison is close; sometimes one predictor is simply much stronger, and the split search correctly reflects that.

## 5a. MAE-based splitting — the outlier-robust alternative

$$\text{MAE}(t) = \frac{1}{n}\sum_{j\in t}|y_j - \text{median}_t|$$

**Why it exists:** MSE-based splitting is quietly dominated by outliers, since a single extreme value contributes its *squared* distance. MAE-based splitting (sklearn's `criterion='absolute_error'`) uses the median as each node's prediction and sums absolute deviations instead — a single extreme outlier contributes proportionally, not quadratically.

### Worked Field Example — Dataset B, the `Sqft <= 1375` split

**Parent:** sorted prices $150,180,190,230,240,300,310,340,380,400$, median $=(240+300)/2=270$.
$$\text{Parent MAE} = \frac{1}{10}\big(120+90+80+40+30+30+40+70+110+130\big) = \frac{740}{10} = 74.0$$

**Left child** (prices 150,180,190,230,240), median $=190$:
$$\text{MAE}_L = \frac{|{-40}|+|{-10}|+0+40+50}{5} = \frac{140}{5}=28.0$$

**Right child** (prices 300,310,340,380,400), median $=340$:
$$\text{MAE}_R = \frac{40+30+0+40+60}{5} = \frac{170}{5}=34.0$$

$$\text{Weighted MAE} = \tfrac12(28.0)+\tfrac12(34.0) = 31.0 \qquad \text{MAE Reduction} = 74.0-31.0 = \mathbf{43.0}$$

Same winning partition as the MSE version (§5), as expected on data with no real outliers — the two criteria only diverge meaningfully when a few extreme values are present (§8 covers why MAE is also structurally slower to compute).

## 6. Twoing Criterion — Multiclass Splitting

$$\text{Twoing}(s) = \frac{p_L\, p_R}{4}\left(\sum_{i}|p_{i|L} - p_{i|R}|\right)^2$$

Plain meaning: rewards splits that make the two children look as *differently composed* as possible (by class mix), rather than directly rewarding within-child purity the way Gini does.

### Worked Field Example — Dataset C, split on `Region == A`

Left (Region A, 3 rows): tier counts low 2, med 1, high 0 → $p_{low|L}=0.667,\ p_{med|L}=0.333,\ p_{high|L}=0$
Right (Region B or C, 6 rows): tier counts low 1, med 2, high 3 → $p_{low|R}=0.167,\ p_{med|R}=0.333,\ p_{high|R}=0.5$

$$\sum_i |p_{i|L}-p_{i|R}| = |0.667-0.167|+|0.333-0.333|+|0-0.5| = 0.5+0+0.5=1.0$$

$$p_L = 3/9 = 0.333,\quad p_R = 6/9=0.667$$

$$\text{Twoing} = \frac{(0.333)(0.667)}{4}(1.0)^2 = \frac{0.222}{4} = \mathbf{0.0556}$$

Not directly comparable in scale to Gini/entropy gains (different formula shape), but usable the same way: compute it for every candidate split and pick the maximum. Not implemented in sklearn; worth recognizing by name for CART-book / multiclass discussions.

## 7. Chi-square (CHAID-style)

$$\chi^2 = \sum \frac{(O-E)^2}{E}$$

Plain meaning: compares observed class counts in each child against what you'd expect if the split were statistically unrelated to the label.

### Worked Field Example — Dataset C, same `Region == A` split

Overall tier proportions in the full 9 rows: low 3, med 3, high 3 → each exactly $1/3$.
Expected counts if the split were unrelated to tier: Left (3 rows) expects 1 of each tier; Right (6 rows) expects 2 of each tier.

| Cell | Observed | Expected | $(O-E)^2/E$ |
|---|---|---|---|
| Left, low | 2 | 1 | 1.0 |
| Left, med | 1 | 1 | 0.0 |
| Left, high | 0 | 1 | 1.0 |
| Right, low | 1 | 2 | 0.5 |
| Right, med | 2 | 2 | 0.0 |
| Right, high | 3 | 2 | 0.5 |

$$\chi^2 = 1.0+0+1.0+0.5+0+0.5 = \mathbf{3.0}$$

Compare this $\chi^2$ value against a chi-square distribution ($df = (\text{rows}-1)(\text{cols}-1) = 1\times2=2$) to get a p-value, which CHAID uses directly as a stopping/significance rule — a fundamentally different philosophy from the impurity-reduction framing of §1-2.

## 8. Comparison — where these methods actually diverge

**Gini vs. entropy in general**: nearly always pick the same split — as seen in the Dataset A worked examples above, both agreed X2 (Age) was better than X1 (Income), just by different margins. The curves have the same concave shape and differ only in how sharply they penalize mixed nodes.

**A constructed case where Gini and entropy genuinely disagree** (100-point, 50/50 synthetic parent, kept separate from Dataset A/B/C since the field datasets are too small to produce a genuine rank-flip cleanly):

| Split | Left | Right | Gini gain | Entropy gain |
|---|---|---|---|---|
| A | (2, 48) | (48, 2) | **0.4232** ← Gini prefers | 0.7577 |
| B | (0, 45) | (50, 5) | 0.4091 | **0.7583** ← Entropy prefers |

Gini ranks A above B; entropy ranks B above A. The two entropy values are extremely close (0.7577 vs 0.7583) — representative of how narrow these disagreements usually are.

**Gini/entropy vs. misclassification error:** already demonstrated live above (§4) — `Age <= 47.5` scores a real, positive gain under Gini (0.12) and entropy (0.281), but *zero* gain under misclassification error, while the weaker `Income == low` split scores a positive 0.10 under misclassification error. **Why, geometrically:** plotted against $p$, misclassification error is piecewise-*linear* (two straight segments meeting at $p=0.5$), while Gini and entropy are strictly *concave*. A strictly concave function credits essentially any split that changes the class mix with some measurable gain; a piecewise-linear one has whole regions where different splits land on the exact same line and score identically. This is the precise, non-empirical reason Gini/entropy — not misclassification error — are the standard criteria for *growing* trees.

**Gain Ratio vs. plain Information Gain:** already covered in §3 with both a real comparison (Age still wins) and the constructed cardinality-bias case (`customer_id`). C4.5's average-gain pre-filter is the standard mitigation for Gain Ratio's own residual bias.

## 9. Computational Complexity of Split Search

**Continuous features:** sort the feature's values ($O(n\log n)$), then sweep candidate thresholds left-to-right. Each candidate's impurity/variance can be updated **incrementally** in $O(1)$ (moving one point between children only needs updating running sums, not full recomputation). Full search for one feature: $O(n\log n)$; across $p$ features at one node: $O(pn\log n)$.

**Categorical features, binary target:** a classical CART theorem says the optimal binary split of a $k$-category feature (2-class problem only) is found by sorting categories by their positive-class rate and checking only the $k-1$ adjacent splits in that order — $O(k\log k)$ instead of the naive $2^{k-1}-1$ exhaustive search. **This shortcut does not hold for regression or multiclass (3+ class) problems**, which need exhaustive or heuristic search (e.g., LightGBM sorts categories by mean target value as a practical, non-provably-optimal proxy).

**MAE-based splitting, why it's slower:** the median (unlike the mean) has no cheap $O(1)$ incremental update as points move between children — maintaining a running median typically needs a two-heap or balanced-BST structure, adding real per-candidate overhead. This is the concrete reason MAE-criterion trees train noticeably slower than MSE-criterion trees, beyond just "outlier robustness has a cost."

## 10. Interaction With Stopping Criteria and Pruning

Split-criterion choice answers "which split is best *among candidates*" — a separate question from "should we split at all," governed by stopping rules:

- **Pre-pruning:** `max_depth`, `min_samples_split`, `min_samples_leaf`, `min_impurity_decrease` — the last one is directly coupled to criterion choice, since it thresholds the *gain* value that criterion computes; switching criteria (Gini → entropy) changes that value's scale and typically needs re-tuning.
- **Post-pruning:** cost-complexity pruning (`ccp_alpha`) grows a full tree, then trims subtrees whose removal doesn't increase a penalized version of the *same* impurity measure used to grow the tree by more than $\alpha$.

**Practical workflow tying back to §4/§7:** since misclassification error is a poor *growing* criterion but is often exactly what you care about at the end, grow with Gini or entropy, then evaluate/prune/report using misclassification error (or F1/RMSE, as appropriate) as the final judgment.

## Master notes — diagnostics

| Symptom | Likely cause | Fix |
|---|---|---|
| Gini and entropy give visibly different "best" splits | Genuinely possible (§8) but rare, and gain values are usually very close when it happens | Don't chase this — check `max_depth`/pruning instead |
| A tree grown with misclassification error underperforms a Gini/entropy tree of the same depth | Misclassification error is piecewise-linear, not concave, so it's blind to purity differences that don't change the majority class (§4, §8) | Grow with Gini or entropy; use misclassification error only as a final reporting metric |
| A high-cardinality categorical feature keeps winning splits near the root | More candidate thresholds → more chances to look good on training data by chance; worse under raw Information Gain specifically (§3) | Use Gain Ratio instead of raw Information Gain; sanity-check with permutation importance after training |
| Regression tree's variance reduction is tiny for every candidate split | Target has little relationship to available features, or parent variance is already low | Check parent MSE first — a tiny gain against a tiny parent MSE may still be a meaningful fraction |
| MSE-criterion regression tree keeps splitting to "chase" a handful of extreme target values | A small number of outliers dominate variance disproportionately (§5a) | Try `criterion='absolute_error'`, or address outliers upstream |
| Categorical multiclass tree is unexpectedly slow to train at each split | The $O(k\log k)$ CART shortcut (§9) only applies to binary-target problems | Reduce category cardinality upstream, or use a library with native heuristic categorical handling |

## Quick interview answers

**Q: "Gini or entropy — which would you use, and does it matter?"**
A: Rarely matters in practice — both are concave impurity measures and almost always agree on the best split; when they disagree it's usually a very close call (§8). Gini is the more common default mostly because it's cheaper to compute (no logarithm).

**Q: "Why isn't misclassification error used to grow trees?"**
A: It's piecewise-linear rather than concave, so it can be completely blind to a split that clearly improves purity — demonstrated directly in §4, where a split that produces a pure child scores *zero* gain under misclassification error while scoring strongly positive under Gini and entropy.

**Q: "How does variance reduction relate to Gini/entropy?"**
A: Same "parent impurity minus weighted child impurity" pattern, just with a different impurity measure — Gini/entropy for class mix, variance for spread of a numeric target.

**Q: "Why does Information Gain favor high-cardinality features, and how is that fixed?"**
A: Fragmenting data into many small, trivially-pure branches inflates raw gain regardless of real predictive value (§3's `customer_id` example, gain $=0.881$, the theoretical max). Gain Ratio divides by Split Info, a measure of how much the split itself fragments the data, penalizing gain that comes mainly from fragmentation.

**Q: "What's the computational complexity of finding the best split at one node, for a continuous feature?"**
A: $O(n\log n)$ — dominated by sorting; each candidate threshold's impurity is then updated in $O(1)$ via running sums rather than recomputed from scratch.

**Q: "Is there an efficient way to find the optimal categorical split?"**
A: Only for binary classification — sort categories by positive-class rate and check only the $k-1$ adjacent splits, $O(k\log k)$ instead of exponential. Doesn't hold for regression or multiclass.

## Practice Q&A

1. A node has 6 "yes" and 4 "no." Compute Gini, entropy, and misclassification error.
2. In Dataset A, explain in one sentence why the `Age <= 47.5` split scores zero gain under misclassification error despite producing a pure child.
3. A regression node has MSE = 900. A candidate split produces a left child (70% of data, MSE = 300) and right child (30% of data, MSE = 600). Compute the variance reduction.
4. Why does chi-square splitting naturally support multi-way splits, unlike Gini/entropy in the CART framework?
5. Two candidate splits have identical Gini gain. Does that guarantee identical entropy gain? Why or why not?
6. A feature has 1,000 unique categories and ranks best under plain Information Gain by a wide margin. What should you suspect, and what's one concrete fix?
7. Why can't the $O(k\log k)$ categorical-splitting shortcut be used for the 3-class Tier target in Dataset C?

---

*Answers below.*

<br><br><br>

1. $p_{yes}=0.6,\ p_{no}=0.4$. Gini $=1-0.6^2-0.4^2=0.48$. Entropy $=-0.6\log_2 0.6-0.4\log_2 0.4=0.971$. Misclassification error $=1-0.6=0.4$.
2. Both children end up on the majority side of $p=0.5$ or exactly pure in a way that the piecewise-linear misclassification-error curve treats identically to the parent's own error rate, since it only tracks the size of the majority class, not how close to pure the split gets it.
3. Weighted child MSE $=0.7(300)+0.3(600)=390$. Variance reduction $=900-390=510$.
4. Chi-square evaluates a candidate grouping via a statistical test on observed vs. expected counts, which naturally extends to $k$ groups at once; Gini/entropy in CART are defined as a weighted sum over exactly two child partitions.
5. No — Gini and entropy are different functions of the same class proportions (as shown by the Dataset A example, where they agree on the winner but by different margins), so two splits can tie under one measure while differing under the other.
6. Suspect cardinality bias inflating raw Information Gain (§3) — the feature may be finding trivially pure, tiny/singleton branches rather than genuine signal. Fix: recompute using Gain Ratio, or check permutation importance after training.
7. The $O(k\log k)$ shortcut relies on a CART theorem specific to two-class problems — sorting categories by a single "positive-class rate" only preserves optimality when there are exactly two classes to rank against. With 3 classes (low/med/high) there's no single scalar to sort by that guarantees the optimal binary partition, so the search reverts to exhaustive or heuristic methods.
