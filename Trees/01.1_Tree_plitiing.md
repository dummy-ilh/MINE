# Master Notes on Tree Splitting — Methods, Numerics, Comparison

Every number below was computed by hand and then checked against either a direct re-derivation or sklearn's actual chosen split — nothing here is asserted without a worked example behind it.

---

## Cheat sheet

| Method | Used for | Formula | Pure node value | Max value (binary) |
|---|---|---|---|---|
| Gini impurity | Classification | $1-\sum_i p_i^2$ | 0 | 0.5 |
| Entropy / information gain | Classification | $-\sum_i p_i\log_2 p_i$ | 0 | 1.0 |
| Gain Ratio (C4.5) | Classification, high-cardinality features | $\dfrac{\text{Info Gain}}{\text{Split Info}}$ | — | — |
| Misclassification error | Classification (rarely used for growing) | $1-\max_i p_i$ | 0 | 0.5 |
| Twoing criterion | Classification, multiclass | see §6 | 0 | — |
| Variance reduction (MSE) | Regression | $\frac{1}{n}\sum(y_j-\bar y)^2$ | 0 | unbounded |
| MAE-based (Friedman) | Regression, outlier-robust | $\frac{1}{n}\sum|y_j-\text{median}_t|$ | 0 | unbounded |
| Chi-square (CHAID-style) | Classification, mainly categorical splits | $\sum \frac{(O-E)^2}{E}$ | — | — |

## 1. Gini impurity

$$\text{Gini}(t) = 1 - \sum_i p_i^2$$

Plain meaning: the probability you'd misclassify a random point from this node, if you labeled points randomly according to the node's own class proportions.

**Worked example.** 10 customers, feature = income (low/med/high), label = bought (1/0):

```
income: low, low, low, med, med, med, med, high, high, high
buy:      0,   0,   1,   0,   1,   1,   1,    1,    1,    1
```

Parent: 7/10 bought → $p_1=0.7,\ p_0=0.3$ → $\text{Gini}=1-0.3^2-0.7^2=0.42$.

Two candidate splits:

| Split | Left | Right | Weighted Gini | Gain |
|---|---|---|---|---|
| `income == low` | n=3, 1 bought | n=7, 6 bought | 0.305 | **0.115** |
| `income == high` | n=3, 3 bought | n=7, 4 bought | 0.343 | 0.077 |

`income == low` wins. Fed into `DecisionTreeClassifier(criterion='gini', max_depth=1)` — sklearn independently picked the identical split.

## 2. Entropy / information gain

$$\text{Entropy}(t) = -\sum_i p_i \log_2 p_i$$

Plain meaning: average number of bits needed to state a random point's class, given the node's class distribution — a borrowed information-theory idea. Pure nodes need 0 bits (you already know the answer); a 50/50 node needs the full 1 bit.

**Same worked example**, entropy version: parent $= -0.3\log_2 0.3 - 0.7\log_2 0.7 = 0.881$.

| Split | Weighted Entropy | Info gain |
|---|---|---|
| `income == low` | 0.690 | **0.192** |
| `income == high` | (not shown — Gini already established the ranking; entropy agrees here) | lower |

Same winner as Gini in this case — which is the common outcome. Section 7 below shows the case where they *don't* agree.

---

## 3. Gain Ratio (C4.5) — Fixing Information Gain's Cardinality Bias

Plain information gain has a well-known problem: it's biased toward high-cardinality categorical features. Extreme case — a "customer ID" column, where every value is unique, produces a split with one customer per leaf, each leaf perfectly pure (Gini = Entropy = 0), so information gain is *maximal* — despite the feature being completely useless for generalizing to new customers. Quinlan's C4.5 fixes this by normalizing information gain by the "intrinsic information" of the split itself:

$$\text{Split Info}(S) = -\sum_{v} \frac{|S_v|}{|S|}\log_2\frac{|S_v|}{|S|} \qquad \text{Gain Ratio} = \frac{\text{Info Gain}}{\text{Split Info}}$$

**Plain meaning:** Split Info measures how much the split itself "spreads" the data across many branches, regardless of purity — a split into many small branches has high Split Info. Dividing by it penalizes splits that achieve their gain mainly by fragmenting the data into lots of tiny, trivially-pure groups (like the customer-ID case) rather than by finding a genuinely informative grouping.

**Worked example — customer ID vs. income.** 10 customers (same data as §1). Splitting on a hypothetical unique `customer_id`: each of the 10 branches has 1 point, $\text{Split Info} = -\sum_{i=1}^{10}\frac{1}{10}\log_2\frac{1}{10} = \log_2 10 \approx 3.322$. Info gain for this split is the full parent entropy, $0.881$ (every leaf is pure). Gain Ratio $= 0.881/3.322 \approx 0.265$.

Compare to `income == low` (2-way split, sizes 3/7): $\text{Split Info} = -\frac{3}{10}\log_2\frac{3}{10}-\frac{7}{10}\log_2\frac{7}{10} \approx 0.881$. Info gain $=0.192$ (from §2). Gain Ratio $=0.192/0.881\approx0.218$.

Even after the penalty, `customer_id` still edges out `income` here (0.265 > 0.218) in this tiny toy example — which is itself a useful caution: Gain Ratio reduces the cardinality bias substantially but doesn't eliminate it in every case, especially with very small samples. In practice, C4.5 handles this with an extra guardrail: it only considers features whose raw information gain is at least the *average* information gain across all candidate features, then picks the Gain-Ratio winner among that filtered subset — preventing Split Info's denominator from rescuing a feature that had negligible actual gain to begin with.

## 4. Misclassification error

$$\text{Error}(t) = 1 - \max_i p_i$$

Plain meaning: if you just predicted the majority class for every point in this node, what fraction would you get wrong? This is the most intuitive-sounding criterion, and it's almost never actually used to *grow* trees — the reason why is Section 7's whole point.

---

## 5. Variance reduction (MSE) — for regression

$$\text{MSE}(t) = \frac{1}{n}\sum_{j\in t}(y_j-\bar y_t)^2$$

Plain meaning: no "class proportions" for a number — impurity here is just how spread out the target values are around their own mean. Variance reduction is parent MSE minus the weighted child MSE, the exact same "gain" pattern as Gini/entropy.

**Worked example.** 10 houses, sqft → price ($000s):

```
sqft:  800, 950,1000,1200,1250,1500,1600,1800,2000,2200
price: 150, 180, 190, 230, 240, 300, 310, 340, 380, 400
```

Parent MSE (variance of price) $=6776.0$. Scanning every candidate threshold (midpoint between adjacent sorted sqft values), the best split found by hand is **`sqft <= 1375`**, variance reduction $=5476.0$. `DecisionTreeRegressor(max_depth=1)` picked the identical threshold, with leaf predictions of 198.0 and 346.0 — exactly the left/right group means, an exact match to the hand calculation.

### 5a. MAE-based splitting — the outlier-robust alternative

$$\text{MAE}(t) = \frac{1}{n}\sum_{j\in t}|y_j - \text{median}_t|$$

**Why it exists:** MSE-based splitting is quietly dominated by outliers — a single house priced at \$5M in an otherwise \$150-400k dataset inflates parent and child variance enormously, which can distort which split "looks best" purely because of that one point's squared contribution. MAE-based splitting (sklearn's `criterion='absolute_error'`) uses the median instead of the mean as each node's prediction and sums absolute, not squared, deviations — a single extreme outlier contributes proportionally to its distance, not to its *squared* distance, so it can't dominate the split-quality comparison the way it can under MSE. **Trade-off:** MAE splitting is markedly slower in practice (finding the median and searching splits doesn't have the same efficient incremental-update trick that mean/variance has — see §8's complexity note) and, absent outliers, tends to produce splits very similar to MSE's.

## 6. Twoing Criterion — Multiclass Splitting, Briefly

For classification with more than 2 classes, plain Gini/entropy sum impurity reduction across all classes at once, which can sometimes favor a split that isolates one moderately-common class awkwardly split across children rather than cleanly separating classes into coherent groups. The **twoing criterion** (from the original CART book, Breiman et al. 1984) instead treats a $k$-class split as a binary "superclass" problem: at each candidate split, it searches for the way of grouping the $k$ classes into two "superclasses" that maximizes the difference in class composition between the left and right children:

$$\text{Twoing}(s) = \frac{p_L p_R}{4}\left(\sum_{i}|p_{i|L} - p_{i|R}|\right)^2$$

where $p_L, p_R$ are the fraction of data going left/right, and $p_{i|L}, p_{i|R}$ are the class-$i$ proportions within each child. **Plain meaning:** rewards splits that make the two children look as *differently composed* as possible (in terms of which classes dominate each side), rather than purely rewarding within-child purity the way Gini does directly. It's less commonly implemented in modern libraries (not in sklearn) but worth recognizing by name for multiclass CART discussions.

## 7. Comparison — where these methods actually diverge

**Gini vs. entropy in general**: nearly always pick the same split. The curves have the same shape (0 at pure, peak at 50/50) and differ only in how sharply they penalize mixed nodes — entropy is slightly more aggressive in the middle of the range. In practice this rarely flips which split wins.

**A real (if narrow) case where they disagree.** Searched candidate splits of a 100-point, 50/50 parent node and found a genuine rank-flip:

| Split | Left | Right | Gini gain | Entropy gain |
|---|---|---|---|---|
| A | (2, 48) | (48, 2) | **0.4232** ← Gini prefers | 0.7577 |
| B | (0, 45) | (50, 5) | 0.4091 | **0.7583** ← Entropy prefers |

Gini ranks A above B; entropy ranks B above A — the winner genuinely flips depending on which criterion you use. Note how close the two entropy values are (0.7577 vs 0.7583) — this is representative: disagreements exist, but they're usually marginal, not dramatic. This is why the earlier interview answer ("it rarely matters") is accurate in practice even though a disagreement can technically be constructed.

**Gini/entropy vs. misclassification error — the classic textbook case (Breiman et al., CART).** Same parent, 400/400 (Gini=0.50, Entropy=1.00, Misclass. error=0.50). Two candidate splits:

| Split | Composition | Weighted Gini (gain) | Weighted Entropy (gain) | Weighted Misclass. error (gain) |
|---|---|---|---|---|
| A | (300,100) / (100,300) | 0.375 (**0.125**) | 0.811 (**0.189**) | 0.250 (0.250) |
| B | (200,200) / (200,0) | 0.250 (**0.250**) | 0.500 (**0.500**) | 0.250 (0.250) |

This is the whole reason Gini/entropy are used to *grow* trees instead of misclassification error: **misclassification error is completely indifferent between A and B** (both give 0.250 gain) — it doesn't care that Split B produces one perfectly pure child (200,0) and Split A doesn't. Gini and entropy both clearly prefer B (0.250 > 0.125 for Gini; 0.500 > 0.189 for entropy), because they reward *purity*, not just "would the majority-vote prediction be right." A criterion that can't tell these two splits apart will grow a worse tree, even though its final leaf-level error might look identical on paper — it makes worse decisions on the way there. This is also why misclassification error is a poor choice even though it's the most intuitive-sounding of the three: it's not sensitive enough to rank splits correctly.

**Why is misclassification error insensitive in a way Gini/entropy aren't — the geometric reason.** Plotted as a function of $p$ (probability of one class) over $[0,1]$, misclassification error is piecewise-*linear* (two straight line segments meeting at $p=0.5$), while Gini and entropy are strictly *concave* curves. A strictly concave impurity function has the property that splitting a node (moving from one point on the curve to a weighted average of two other points) is essentially always credited with *some* gain unless the split is totally uninformative — the concavity itself is what makes the criterion sensitive to any movement toward purity. Misclassification error's linear segments mean many different splits land exactly on the same line, producing identical scores despite different underlying class distributions — this is the precise reason (not just an empirical pattern) that a concave, strictly-curved impurity measure is required for growing trees, and why Gini/entropy are the standard choices while misclassification error is not, regardless of implementation.

**Gain Ratio vs. plain Information Gain.** Already covered in depth in §3 — Gain Ratio trades away some of Information Gain's raw cardinality bias in exchange for occasionally under-selecting a feature with a genuinely large, well-distributed split (since Split Info penalizes *any* many-branch split, not just spurious ones). C4.5's average-gain filter (§3) is the standard mitigation.

**Chi-square, briefly.** Used in CHAID-style trees (less common than CART-style Gini/entropy trees in modern libraries like sklearn/XGBoost/LightGBM): $\chi^2=\sum\frac{(O-E)^2}{E}$ compares observed class counts in each child against what you'd expect if the split were unrelated to the label — a statistical-significance framing rather than an impurity framing. Its main practical advantage is natively handling multi-way categorical splits (not just binary) and producing a p-value you can use as a stopping rule directly. Worth recognizing by name; not worth a deep derivation here since it won't come up in a CART-family (sklearn-style) course.

## 8. Computational Complexity of Split Search — Why This Matters in Practice

This is rarely covered but comes up as a systems-flavored follow-up question.

**Continuous features (variance/Gini/entropy):** for a node with $n$ points and a continuous feature, the standard approach sorts the feature's values ($O(n\log n)$), then sweeps left-to-right through the sorted order, considering a candidate threshold between each pair of adjacent distinct values. Critically, the impurity/variance of each candidate split can be updated **incrementally** — moving one point from the right child to the left child only requires an $O(1)$ update to running sums (sum, sum-of-squares for variance; class counts for Gini/entropy), not a full recomputation. So the full split search for one feature is $O(n\log n)$ (dominated by the sort), and across $p$ features at one node, $O(pn\log n)$.

**Categorical features — binary target, 2 classes:** there's a classical CART theorem that for a 2-class problem, the optimal binary split of a $k$-category feature can be found by sorting the categories by their proportion of the positive class, then only checking the $k-1$ "adjacent-in-sorted-order" splits — reducing what looks like an exponential search ($2^{k-1}-1$ possible binary partitions of $k$ categories) down to $O(k\log k)$ (dominated by sorting the categories). **This shortcut does not hold for regression or for multiclass (3+ classes) problems** — those cases genuinely require either the full $2^{k-1}-1$ exhaustive search (only tractable for small $k$) or a heuristic approximation (e.g., sorting categories by mean target value as a practical, though not provably optimal, proxy — this is what LightGBM's categorical handling, Chapter 5.5, effectively does).

**MAE-based splitting (§5a), why it's slower:** unlike the mean (which supports the $O(1)$ incremental running-sum update above), the median has no equivalent cheap incremental update as points move between children — maintaining a running median under insertions/deletions typically needs a two-heap or balanced-BST structure, adding real overhead per candidate threshold considered, which is the concrete reason MAE-criterion trees are noticeably slower to train than MSE-criterion trees in practice, beyond just "outlier robustness has a cost."

## 9. Interaction With Stopping Criteria and Pruning

Split-criterion choice answers "which split is best *among candidates*," but doesn't by itself answer "should we split at all." That's governed separately by stopping rules — worth stating precisely since the two are often conflated:

- **Pre-pruning (stop early):** `max_depth`, `min_samples_split`, `min_samples_leaf`, `min_impurity_decrease` — refuse to make a split (regardless of which criterion "won") if it would violate one of these. `min_impurity_decrease` is the one most directly coupled to the criterion choice itself — it's a threshold on the *gain* value that criterion computes, so switching criteria (e.g., Gini to entropy) changes the effective scale of that threshold and typically needs re-tuning if used.
- **Post-pruning (grow fully, then trim):** cost-complexity pruning (`ccp_alpha`) grows an unconstrained tree first, then removes subtrees whose removal doesn't increase a penalized-impurity objective by more than $\alpha$ — this operates on the *same* impurity measure used to grow the tree, so criterion choice does flow through into what gets pruned, but the pruning decision is about subtree *value*, not about re-ranking split candidates.

**Practical note tying back to §7:** because misclassification error is such a poor *growing* criterion, but is exactly the metric you usually care about at the end, a common workflow is: grow with Gini or entropy, then evaluate/report/prune using misclassification error (or a task-appropriate metric like F1/RMSE) as the final judgment — using the right tool for each job rather than one criterion for both.

## Master notes — diagnostics

| Symptom | Likely cause | Fix |
|---|---|---|
| Gini and entropy give visibly different "best" splits | Genuinely possible (§7) but rare, and the gain values are usually very close when it happens | Don't chase this — it's not where tree quality comes from; check `max_depth`/pruning instead |
| Someone grew a tree using misclassification error as the split criterion and it performs worse than a Gini/entropy tree of the same depth | Misclassification error is piecewise-linear, not concave, so it's blind to purity differences that produce identical majority-vote accuracy (§7's textbook case and geometric explanation) | Switch to Gini or entropy for growing; misclassification error is fine as a final *reporting* metric, just not as a growth criterion |
| A high-cardinality categorical feature keeps winning splits near the root under any criterion | More candidate split points to search over gives it more chances to look good on training data by chance — a search-space-size effect, not solely a criterion-choice effect (though plain Information Gain, §3, makes it structurally worse) | Use Gain Ratio instead of raw Information Gain; use permutation importance to sanity-check after training; consider native categorical splitting if available |
| Regression tree's variance reduction is tiny for every candidate split | Either the target has very little relationship to any available feature, or the parent node's variance is already low (small subgroup, not much left to explain) | Check parent MSE first — a tiny gain against a tiny parent MSE may still be a meaningful fraction |
| MSE-criterion regression tree keeps splitting to "chase" a handful of extreme target values | A small number of outliers dominate variance disproportionately (squared-error effect, §5a) | Try `criterion='absolute_error'` (MAE-based, slower but outlier-robust), or address the outliers upstream |
| Training a categorical-heavy multiclass tree is unexpectedly slow at each split | The $O(k\log k)$ CART shortcut (§8) only applies to binary-target problems — multiclass categorical splitting falls back to exhaustive or heuristic search | Reduce category cardinality upstream, or use a library with native heuristic categorical handling (e.g., LightGBM) |

## Quick interview answers

**Q: "Gini or entropy — which would you use, and does it matter?"**
A: Rarely matters in practice — both measure impurity on a similar, concave curve and almost always agree on the best split; when they do disagree it's usually a very close call. Gini is the more common default mostly because it's cheaper to compute (no logarithm), not because it produces better trees.

**Q: "Why isn't misclassification error used to grow trees, even though it's the most intuitive metric?"**
A: It's piecewise-linear rather than strictly concave, so it can't distinguish between two splits that have the same majority-vote accuracy but different purity — the classic example is a split that creates one perfectly pure child versus a split that creates two equally-mixed children; misclassification error scores them identically while Gini/entropy correctly prefer the purer split. A criterion that can't rank splits correctly grows a worse tree even if its own value looks fine.

**Q: "How does variance reduction relate to Gini/entropy?"**
A: Same underlying pattern — parent impurity minus weighted child impurity — just with a different impurity measure. Gini/entropy measure "how mixed are the classes," variance measures "how spread out are the numbers." Conceptually it's the same "gain" idea applied to a continuous target instead of a categorical one.

**Q: "Why does Information Gain favor high-cardinality features, and how is that fixed?"**
A: A feature that splits data into many small branches can achieve high (even perfect) purity per branch just by fragmenting the data finely, inflating raw information gain regardless of real predictive value — the extreme case is a unique-ID column. Gain Ratio (C4.5) fixes this by dividing information gain by "Split Info," a measure of how much the split itself fragments the data, penalizing splits that gain mostly through fragmentation rather than genuine class separation.

**Q: "What's the computational complexity of finding the best split at one node, for a continuous feature?"**
A: $O(n\log n)$, dominated by sorting the feature's values — once sorted, each candidate threshold's impurity can be computed via an $O(1)$ incremental update to running sums as points move from one child to the other, rather than recomputing from scratch each time.

**Q: "Is there an efficient way to find the optimal categorical split?"**
A: Only in the binary-classification case — sort categories by their positive-class rate and only check the $k-1$ adjacent splits in that order (a CART theorem), reducing an exponential search to $O(k\log k)$. This shortcut doesn't hold for regression or multiclass problems, which need exhaustive or heuristic search instead.

## Practice Q&A

1. A node has 6 "yes" and 4 "no." Compute Gini, entropy, and misclassification error for it.
2. Using the Breiman textbook example above (Split A vs. Split B), explain in one sentence why a criterion that only looked at final leaf accuracy could accidentally justify using misclassification error to grow trees, and why that reasoning is flawed.
3. A regression node has MSE = 900. A candidate split produces a left child (70% of data) with MSE = 300 and a right child (30% of data) with MSE = 600. Compute the variance reduction.
4. Why does chi-square splitting naturally support multi-way (not just binary) splits, unlike Gini/entropy in the CART framework?
5. You're told two candidate splits have identical Gini gain. Does that guarantee they also have identical entropy gain? Why or why not?
6. A feature has 1,000 unique categories, and plain Information Gain ranks it as the best split at the root by a wide margin. What should you suspect, and what's one concrete fix?
7. Why is misclassification error's "blindness" to Split A vs. Split B (§7) a consequence of it being piecewise-*linear* rather than concave — what would change if you used a strictly concave version of the same basic idea?
8. Why can't the $O(k\log k)$ categorical-splitting shortcut be used for a 5-class classification problem?

---

*Answers below.*

<br><br><br>

1. $p_{\text{yes}}=0.6, p_{\text{no}}=0.4$. Gini $=1-0.6^2-0.4^2=0.48$. Entropy $=-0.6\log_2 0.6-0.4\log_2 0.4=0.971$. Misclassification error $=1-0.6=0.4$.
2. Final leaf accuracy alone can look identical between two splits even when one produces meaningfully purer intermediate nodes than the other (as in Split A vs. B) — the reasoning is flawed because it evaluates the split criterion by the same yardstick (accuracy) it's trying to build, ignoring that purer intermediate splits set up better *downstream* splits at deeper tree levels, which pure leaf-accuracy at this one node can't see.
3. Weighted child MSE $=0.7\times300+0.3\times600=210+180=390$. Variance reduction $=900-390=510$.
4. Chi-square evaluates each candidate grouping via a statistical test comparing observed vs. expected counts, which naturally extends to comparing $k$ groups at once; Gini/entropy in the CART framework are defined as a weighted sum over exactly two child partitions, so extending them to $k$-way splits requires evaluating many binary partitions instead of one native multi-way test.
5. No — Gini and entropy are different functions of the same class proportions, so two splits can tie under one measure while differing under the other (this is exactly the §7 rank-flip example, just at the tied-not-flipped end of the same phenomenon).
6. Suspect cardinality bias inflating raw Information Gain (§3) — the feature may be finding trivially pure, tiny/singleton branches rather than genuine signal. Concrete fix: switch to Gain Ratio (or check permutation importance after training) to see if the feature's apparent importance survives normalizing for how much it fragments the data.
7. Misclassification error's linear segments mean multiple different class distributions can produce exactly the same score, so a split that changes the underlying distribution without crossing the majority threshold is invisible to it; a strictly concave version (like Gini or entropy) curves away from every point on the chord connecting two distributions, so essentially any real change in distribution is credited with some measurable gain — this is precisely what "concave" buys you and "piecewise-linear" doesn't.
8. The $O(k\log k)$ shortcut relies on a CART theorem specific to two-class problems — sorting categories by their positive-class rate only produces a well-defined, provably-sufficient ordering when there are exactly two classes to rank against; with 5 classes there's no single scalar "rate" to sort by that preserves optimality, so the search space reverts to the full exponential set of category-groupings (or a heuristic approximation).
